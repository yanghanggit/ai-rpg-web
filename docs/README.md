## 写作边界

- **只记录「当前是怎么做的」和「为什么这么做」，不记录进度、计划与待办**——代码是唯一事实，写下来的计划第二天就过期。
- 只写**读代码看不出来的信息**：设计意图、被否决的方案、容易踩的坑。字段名 / 函数名这类代码能自述的内容不复述。
- 每篇聚焦一个主题，交叉引用用相对链接，**不复制内容**（复制必然漂移）。
- 新增约定时先想「谁保证它」：能工具强制的就工具强制，见 [开发规范 §七](conventions.md)。
